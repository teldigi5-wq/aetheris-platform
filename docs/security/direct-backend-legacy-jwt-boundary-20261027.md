# Actual User and Audit service authentication — transitional HMAC JWT boundary

**27 October 2026 · DRAFT · NOT PRODUCTION CERTIFIED · NO_GO**

This stage builds on main-based security PR #315 and the first closure checkpoint PR #322, not the incompatible newer Boot 4/RS256 B62-G stack. It implements **actual** `@Component` servlet JWT filters within the User and Audit services, matched to the **existing** Identity `JwtService` HMAC key/token shape (`uid`, `role`, `scopes`, `sub`, signed `iat` and `exp`). This is a substantive improvement over relying only on Gateway headers. Both services reject protected requests without a key; a missing/too-short key returns 503 instead of accepting requests. No key or sensitive token content is logged.

A real JJWT verification in each backend checks signature and signed claims and then enforces role **and** route/method scope, independent of any `X-Aetheris-*` headers. User listing, creation, deletion and privileged object lookup require ADMIN/DEVELOPER and appropriate signed `users:read`/`users:write` scope. Audit `/api/events` requires ADMIN/DEVELOPER plus `services:read`. Unexpected methods and nested paths fail closed. Invalid/wrong-key/expired/foreign-role or malformed-UID tokens are rejected before controllers run, tested with **real MockMvc servlet filter chains**.

**Critical owner boundary:** An `IdentityAccount.uid` is not proven to map to the same person as `User.id`. Thus the filter **denies API_CONSUMER requests for any `/api/users/{id}` object**, even when numeric IDs match, until a real identity-to-resource-owner/tenant relation is implemented and tested. Privileged ADMIN/DEVELOPER routes are still broad; tenant-scoped authorization remains open (#251). This does NOT claim full IDOR/tenant isolation, signed approval, or workload-to-workload identity.

**Legacy format limitation:** The Identity/Gateway signer currently uses a shared HMAC secret (not RS256 and not a separate private signing service). A compromised component holding that secret can forge roles/scopes. This interim direct-backend control must be reconciled with the independently reviewed RS256 issuer/audience/kid/rotation and emergency revocation stack; don't merge incompatible branches blindly. The local source closure gate is still **NO_GO** because all three Compose variants retain Hibernate automatic `update`, historical migration/restore (#242) and a real tenant binding remain unverified. No customer migration/secret rotation/production deploy is attempted.

A green Java suite here is only pre-release code verification. The final release still requires signed owner approval, exact real runtime images and CA trust, secret migration on existing DB volumes, resource/tenant authorizations, actual live revocation clients, supply-chain advisories (#255/#259), emergency audit and nine runtime gates. Protected `main` remains unchanged.
