## Why this checkpoint exists

PR #401 used actual User publishing classes, RabbitMQ4 messages, RSA signature verification, and PostgreSQL16 persistence across two Java test processes. However, the Audit test **called `AuditEventStore.consume(Map)` directly** and read a test queue using a privileged CI observer. This did not prove that the application's real annotated `@RabbitListener` container started, connected with its own least-privilege broker identity, handled signed JSON automatically, acknowledged valid events and rejected poisoned events to a configured DLQ.

## What this exact new workflow actually runs

After the previously inherited 3-DB restore, broker vhost/ACL/inflight, signed replay and cross-JVM checks have run and the real service JARs are packaged, the CI script:

1. Validates the uniquely named hosted runner and disposable Compose project. Creates fresh RSA-3072 PKCS#8 synthetic private and public keys under a mode-0700 `RUNNER_TEMP` directory, and a separate `xerj_origin_listener` RabbitMQ vhost and `xerj_origin_consumer` credential with a strictly read-only grant on **only** `aetheris.audit.user-events`. The already-existing `xerj_publisher` principal gets **write-only** access to **only** `aetheris.events` in this new vhost; it cannot read queues or manage topology. The admin identity is used solely in fixture creation and a final CI observer; not passed into the actual Audit application.
2. The first independent Maven/JVM test invokes the **real** User service's `UserEventPublisher` with `UserEventOriginSigner`, sends seven events into the precreated real-contract queue and DLX: one signed direct event; a valid signed duplicate pair (same event ID); one signed legacy tenantless event; unsigned event; tenant-modified post-signature event; an event signed with an unrelated RSA private key. It writes only run-unique synthetic marker names into runner temp. The **private signing key never enters Audit service environment**.
3. The script launches the **real packaged `audit-service` Spring Boot JAR** with `AETHERIS_AUDIT_ORIGIN_VERIFY_REQUIRED=true`, pinned public-only RSA verifier and KID, exact `xerj_origin_listener` vhost, `xerj_origin_consumer` broker username and isolated password, and `SPRING_RABBITMQ_DYNAMIC=false` so the read-only consumer cannot create arbitrary queues. Flyway is disabled only for the **already provisioned disposable restored Audit fixture database**; this is not a production migration or a way around schema approval. The script explicitly verifies that a live RabbitMQ consumer registered on `aetheris.audit.user-events`, rather than treating an HTTP health response or unit test as evidence of listener startup.
4. A **second Maven/JVM observer test** never calls `AuditEventStore.consume`. It independently watches the disposable Audit Postgres rows and the actual broker DLQ for the event outcomes. It requires exactly **three unique persisted events**, including tenantless historical attribution and at-least-once duplicate idempotency, and **three absent invalid events** recorded in the isolated DLQ. It validates the source/DLQ empty and the original synthetic recovery-fence and tenant row preserved. It reports check labels only, no customer payloads or private-key material.
5. A strict shell exit trap stops only that ephemeral Audit JAR, deletes the isolated listener vhost/consumer user, and removes its runner-local key and synthetic marker directory. The overarching Compose cleanup still deletes only the unique CI project; **the existing `xerj_review` recovery queue and its custody test remain unchanged**.

The new source and script are constrained to the child draft PR. At the revised **exact commit**, inherited 121 Java security tests, 90 existing real RSA/mTLS/outbox checks, original RabbitMQ whole-vhost custody, synthetic epoch-witness and signed replay proofs must also pass before declaring this checkpoint CI-verified. **Unverified until an exact-head SUCCESS is observed.**
