## Repository topology

Aetheris is now intentionally split across two source owners:

- **Platform:** `teldigi5-wq/aetheris-platform`
- **AI runtime:** `teldigi5-wq/aetheris-ai-runtime`

The platform owns gateway, identity, user, audit, dashboard, deployment/integration contracts, platform observability assets and cross-repository certification references.

The AI runtime owns `orchestrator-service/`, `workstation-agent/`, `aetheris-reasoning/` and `aetheris-quant/`, including the runtime-side orchestration, browser/operator, reasoning, PC-care and trading-intelligence implementations and their applicable certification workflows.

The platform records `68af39a1115a7330020c18b6e2cb601e66b8f22f` as the certified runtime checkpoint. A newer runtime `main` commit is not automatically certified merely because it is newer or because documentation-only CI passes.

## Safety and governance boundaries

The following remain non-negotiable for this release class:

- deterministic owner policy outranks model recommendations;
- `ALLOW` means eligible to execute, not proof that execution occurred;
- success requires verification evidence or an explicit `UNVERIFIED` result;
- emergency precedence remains `STOP > TAKE_CONTROL > PAUSE > NORMAL`;
- protected/private data and billable fallbacks remain constrained by owner policy;
- browser mutations and consequential external actions remain approval/evidence gated;
- live-money execution, withdrawals and transfers remain outside the default trusted AI path;
- hosted CI is repository evidence, not physical-PC validation;
- `BLOCKED_PENDING_HARDWARE` remains the physical-machine state until real target-machine evidence exists.

## Administrative ruleset gate

The repository currently has an active ruleset named **`Protect stable main`**. Its required-status list was created before the runtime extraction and still contains legacy check contexts, including platform-local `workstation-agent` and `pc-care-simulation`, plus older names such as `backend` and `Analyze Java`.

Before publishing `v0.1.0-pre-pc`, the GitHub ruleset must be administratively aligned with the current split-repository platform checks. Repository source or CI must **not** add fake compatibility jobs merely to satisfy obsolete administrative names.

## Known limitations

This candidate intentionally does not claim validation of:

- WSL2 or virtualization on the final owner PC;
- Docker Desktop/runtime behavior on that machine;
- RTX GPU acceleration or local-model throughput;
- thermal, storage or long-duration resource behavior;
- microphone/speaker/voice hardware;
- ChromeDriver/EdgeDriver installation or browser launch behavior on the real machine;
- authenticated browser profiles, cookies or session persistence on the real machine;
- LinkedIn-, Vercel-, Facebook-, Instagram- or other site-specific workflow stability on the owner PC;
- unrestricted privileged host execution;
- production deployment readiness outside the declared repository scope;
- registry publication of the certified runtime image;
- live-money trading execution.

Physical-PC validation remains pending.
